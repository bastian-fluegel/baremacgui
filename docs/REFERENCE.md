# BareMacGUI API reference

Generated by `tools/make_reference.py` from the docstrings. Do not edit by hand.

Handlers take no arguments. Every event can be given as an `on_*=` option, registered with `control.on_x(handler)`, used as a decorator, or replaced by assignment.

## App and errors

### `App(name=None, menu=True, background=False, icon=None)`

```text
Create one App before any Window, then call run().

name  shown in the menu bar entries (best effort for a plain script; a
      packaged .app takes its name from its bundle)
menu  install the standard App/Edit/Window menus (needed for Cmd+C/V/Q)
icon  path of an image (.icns or .png) for the Dock icon while the app runs. A script started from an
      .app built with `python -m baremacgui build ... --icon` gets it without this argument.
background  a menu-bar app: no Dock icon, no menu bar of its own, and it keeps running when the
      last window closes (use it with StatusItem; quit with app.quit() from a menu item).
      Native counterpart: activation policy "accessory" (LSUIElement in a packaged app).
```

Properties:

- `on_error`: Function that receives an exception raised in any handler (instead of the terminal).

Methods:

- `call(function, *args, **kwargs)`: Run function(*args, **kwargs) on the UI thread and return its result.
- `invoke(function, *args)`: Run function(*args) on the UI thread. Call this from worker threads.
- `quit()`: Quit the app. Safe to call from a menu item: it terminates once the menu has closed.
- `run()`: Show the windows and run until the last one is closed (Ctrl-C in the terminal quits too).

### `Event()`

```text
An ordered list of handlers.
```

Methods:

- `clear()`
- `connect(handler)`
- `disconnect(handler)`
- `emit()`: Call all handlers in registration order.

### `BareMacGUIError(...)`

```text
Base class for all BareMacGUI errors.
```

### `PlatformError(...)`

```text
Raised when a macOS-only feature is used on another platform or without PyObjC.
```

### `LayoutError(...)`

```text
Raised for invalid layout configuration (bad option values, misuse of containers).
```

## Windows and layout

### `Window(title, size=(640, 480), resizable=True, visible=True, style='standard', autosave=None, **options)`

```text
A top-level window. Takes exactly one child, normally a VBox or HBox.

size is the initial content size in points; the minimum size follows from
the content. The window shows itself when its with-block ends.

autosave          a name: the window remembers its position and size between runs
                  (NSWindow frame autosave; the frame is stored in the app's own preferences)
on_close          a function: return False to keep the window open (also set as `on_close=`)
on_resize         event, fired while the window is resized (read `win.size`)
on_destroy        event, fired when the window closes

style="standard"  the usual title bar
style="sidebar"   System-Settings-like: a Sidebar on the left lists pages, the chosen page
                  shows on the right. The window then holds a `with Sidebar():` block
                  and nothing else.
style="unified"   Finder-like: no title text, a transparent title bar, and the
                  content starts below it. Put controls in the title bar with a
                  `with Toolbar():` block directly inside the window.
```

Events: `on_destroy`, `on_resize`

Properties:

- `cancel_button`: The button Escape clicks.
- `default_button`: The button Return clicks (also while typing in a text box).
- `size` (read-only): Content size (width, height) in points.
- `title`

Methods:

- `accept(item)`
- `add_shortcut(keys, handler)`: Call handler() when `keys` ("Cmd+K", "F5", "Escape") is pressed while this window is key.
- `close()`: Close the window (like the red button: on_close may veto).
- `destroy()`: Close the window without asking on_close.
- `show_modal()`: Show the window and wait until it is closed; other windows of the app are blocked.

### `Sheet(parent, size=(400, 200), resizable=False)`

```text
A window that slides down from the top of a parent window and blocks only that window.

    with Sheet(win, size=(360, 160)) as sheet:
        with VBox(padding=20):
            ...
            Button("Close").on_click(sheet.close)
    sheet.show()

It is built like a Window (one child) but does not appear until show().
```

Events: `on_destroy`, `on_resize`

Properties:

- `cancel_button`: The button Escape clicks.
- `default_button`: The button Return clicks (also while typing in a text box).
- `is_open` (read-only)
- `size` (read-only): Content size (width, height) in points.
- `title`

Methods:

- `close()`: Slide the sheet away again.
- `show()`: Slide the sheet down over the parent window.

### `Popover(transient=True)`


### `Toolbar()`

```text
Put controls into the window's title bar. Use it directly inside a Window:

    with Window("Files", style="unified"):
        with Toolbar():
            Button("", symbol="chevron.left")
            Spacer()
            SearchField()
        with VBox(): ...

Controls appear left to right. Spacer() is flexible space, Spacer(size=n) a
fixed gap. Controls keep their natural size unless you give width/min_width.
```

Methods:

- `accept(item)`

### `SplitView(orientation='horizontal', min_pane=120, fixed=(), divider='thin', autosave=None, grow=1, **size)`

```text
Two or more panes separated by draggable dividers (native NSSplitView).

    with SplitView(fixed=[0], min_pane=160, autosave="main-split", grow=1) as split:
        with VBox(padding=8): ...      # pane 0
        with VBox(padding=8): ...      # pane 1

orientation  "horizontal": panes side by side (default); "vertical": stacked
min_pane     smallest size of a pane in points; the user cannot drag below it
fixed        pane indexes that keep their size when the window grows; the others take the space
divider      "thin" (default), "thick" or "pane"
autosave     a name: the divider positions are remembered between runs

Each child (normally a VBox or HBox) is one pane. `split.set_position(0, 220)` moves a divider
from code (points from the start edge). Differences from native: panes cannot collapse by
dragging past the minimum, and panes cannot be added after the with-block.
```

Properties:

- `count` (read-only)

Methods:

- `accept(item)`
- `position(divider_index)`: Size of the panes before a divider in points (where the divider sits).
- `set_position(divider_index, points)`: Move a divider (0 = between the first two panes) to `points` from the start edge.

### `Table(columns, rows=(), multi=False, header=True, striped=False, grow=0, editable=False, sortable=False, kinds=None, widths=None, **size)`

```text
A scrollable table of text cells with a header row.

columns   titles, e.g. ["Name", "Size"]
rows      list of rows; every row has one cell per column (cells become strings)
multi     allow several rows to be selected

input does.
```

## Timer, settings and clipboard

### `Timer(interval, handler=None, repeat=True, start=True, **options)`

```text
Calls on_tick on the UI thread every `interval` seconds.

    clock = Timer(1.0, update_clock)            # starts at once
    once = Timer(3, hide_hint, repeat=False)
    clock.stop(); clock.start()

start=False creates it stopped. The timer keeps running while a menu is open
or a window is resized (it runs in the common run-loop modes).
```

Events: `on_tick`

Properties:

- `interval`
- `running` (read-only)

Methods:

- `start()`: (Re)start the timer; the first tick comes after one interval.
- `stop()`

### `Settings(name=None, defaults=None, domain=None)`

```text
A small persistent dictionary.

    prefs = Settings("my-tool", defaults={"theme": "System", "recent": 10})
    prefs["theme"]                 # "System" until something else was stored
    prefs["recent"] = 20           # written to ~/Library/Preferences/baremacgui.my-tool.plist
    del prefs["recent"]            # back to the default

Values may be bool, int, float, str and lists or dicts of those (what a property list holds).
`name` becomes the preferences domain "baremacgui.<name>". A packaged .app would normally use
its own bundle identifier instead; pass `domain="com.example.app"` for that.

Native counterpart: NSUserDefaults (a custom suite). Difference: the domain is not the
script's bundle, because a plain Python process has none of its own.
```

Methods:

- `clear()`: Forget everything stored (defaults stay).
- `get(key, default=None)`
- `keys()`: Names of all stored values and defaults.
- `save()`: Write to disk now. Done automatically in the background; call it before a hard exit.
- `to_dict()`

## Packaging

### `build_app(script, name=None, dest='.', identifier=None, version='1.0', icon=None, background=False, include=(), python=None)`

```text
Create `<dest>/<name>.app` around `script` and return its path.

icon        an .icns file, or a .png (converted with sips and iconutil on macOS). Without one, a plain
            default icon (a blue square with a small window) is made on macOS.
background  a menu-bar app without Dock icon (LSUIElement), for use with StatusItem
include     further files or folders copied next to the script (they are in the working directory)
python      interpreter to start; default: the one running this code

An existing bundle of the same name is replaced.
```

### `build_standalone(script, name=None, dest='.', identifier=None, version='1.0', icon=None, background=False, include=())`

```text
Create a self-contained `<dest>/<name>.app` (own interpreter and PyObjC inside) and sign it ad hoc.

Needs macOS and PyInstaller (`pip install pyinstaller`, only for building, not for running the app).
The result starts without any Python installed. It is bytecode bundled with an interpreter, not
compiled machine code. The ad-hoc signature carries no identity and is not notarized: on the Mac
that built it the app starts without a warning, a copy downloaded elsewhere is blocked by Gatekeeper
until the user allows it. `include` files end up in the bundle's Resources; find them via
`sys._MEIPASS` (unverified on a real Mac so far).
```
